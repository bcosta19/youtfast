# YouTFast 0.9.1

Plays videos with libmpv older than 0.42 by retrying streams YouTube refuses
until they are available, reports a missing or failing yt-dlp, fixes the
Windows installer's `PATH`, and updates two dependencies for security
advisories. The Homebrew tap, Winget manifests and website now follow each
published release automatically.

## Included

- **Playback on older libmpv**: YouTube refuses a stream with HTTP 403 for a
  few seconds after handing it out (until its `available_at`). libmpv 0.42+
  waits for that time; with older libmpv (Omarchy's stable mirror, Ubuntu,
  Debian, Fedora) YouTFast now retries the stream after 0, 1, 3 and 7 seconds
  instead of failing with "Could not play this video. The player did not
  identify the cause." A video may start a few seconds late there.
- **yt-dlp failures named**: playback says when yt-dlp could not be started
  or could not get a video's streams, instead of "mpv could not recognize the
  stream format."
- **Windows installer `PATH`**: the setup installer launches YouTFast with the
  `PATH` that includes the yt-dlp and Deno it just installed through winget,
  and tells the desktop to reload `PATH` for programs started afterwards.
- **Security**: `rustls-webpki` 0.103.17 rejects certificate paths through
  the distrusted emSign intermediates (RUSTSEC-2026-0382); `ctutils` 0.4.8
  fixes RUSTSEC-2026-0385. CI now fails on known advisories and on licences
  incompatible with GPL-3.0-only (`cargo deny`).
- **Distribution**: publishing a release updates the Homebrew tap
  (`brew install --cask bcosta19/tap/youtfast`), submits the Winget manifests
  and deploys the website; release notes list install commands and every
  asset's SHA-256.

## Packages

Linux x86_64 native, Flatpak and Arch; Windows x86_64 installer and portable
ZIP; macOS 15+ Apple Silicon; locked Rust sources, matching native sources,
notices, channel manifests and SHA-256 checksums. Native Linux needs glibc
2.39+, libmpv with Lua (0.42+ recommended; older versions start videos a few
seconds late), and current yt-dlp and Deno; Windows and macOS bundle libmpv
but require yt-dlp and Deno separately. Flatpak includes its playback and
extraction tools.

## Not included

- Flathub or AUR publication, acceptance of the Winget submission by
  `microsoft/winget-pkgs`, Windows publisher signing (Authenticode) or macOS
  notarization.
- Intel macOS, Windows ARM64 or Linux ARM64 packages.
- Bundled yt-dlp and Deno in Windows packages, or a bundled Cast helper.

## Known limitations

- Windows and macOS automated builds do not establish interactive playback,
  graphics or credential-store coverage; platform QA remains tracked in
  [#5](https://github.com/bcosta19/youtfast/issues/5) and
  [#6](https://github.com/bcosta19/youtfast/issues/6).
- The Arch package's `mpv>=0.42.0` dependency does not stop pacman from
  installing it beside Arch's `mpv 1:0.41`, because of the package epoch; on
  0.41 playback relies on the retries above.
- Windows Credential Manager may reject sessions larger than 2560 bytes.
  Browser-session import additionally needs Python and its yt_dlp module.
- Flatpak cannot read host browser profiles; use cookies.txt or stay signed out.
  The standalone Flatpak bundle has no automatic update remote.
- Casting remains unqualified on physical Chromecast and Google TV devices.
  YouTube changes can break playback extraction; keep yt-dlp current.
